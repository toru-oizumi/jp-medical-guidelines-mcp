## 抽出の方式（判断の記録）

初期スキャフォールドの `extract.ts` は、行頭の `1.2.3` を正規表現で見出しとみなす方式だった。
実際の PDF で確かめたところ、次の理由で **1 件も見出しを拾えない** 状態だった。

- 厚労省 GL の見出しは全角数字で、番号と見出し文字の間に空白が無い（`１．１安全管理に…`）。
  `１．1．１`（全角・半角の混在）や `３．２．`（末尾ドット）の揺れもある
- 総務省・経産省 GL は章番号（`1.`）と一部の 3 階層目の番号（`1.1.1.`）が**テキスト層に無い**。
  描画はされている（ページを画像化して確認）が、文字としては取り出せない

そこで、**目次を正として本文の行と順番に照合する**方式に変えた（`scripts/lib/structure.ts`）。

- 本文の「15 年法律…」のような数字始まりの行を見出しと誤認しない
- 番号がテキスト層に無い見出しは、目次の並び（字下げ・フォントサイズ）から番号を補い、`numberInferred: true` を付ける
- 目次と本文で表記が違う見出しがある（目次の誤字「アクセスしてｋ等」、総務省 GL 1.1.2 の略記など）。
  番号が一致する行・本文より大きい字の行に限り、bigram の包含率で照合する
- 見出し文字列は本文側の原文を採る（目次側の誤字を持ち込まない）

## この環境での制約

- 実行環境のネットワーク設定で `www.mhlw.go.jp` と `www.meti.go.jp` への接続が拒否される。
  そのため `npm run fetch` と `scripts/check-updates.ts` はここでは検証していない。
  クラウド環境の設定（Network access の Allowed domains）に両ドメインを追加すれば、この環境でも実行できる。

## 既知の制約

- 図・表の中の文字（本文より小さい字）と脚注番号（上付き）は落としている。表は行単位の文字列になる
- 脚注の本文は、ページ下部のテキストとして節の本文に残る
- `numberInferred` の番号は機械的な推定。原本の表示と一致することは一部のページでしか目視していない
- 目次に無い深い見出し（総務省 GL 5.1.5 配下の「リスク対応策の設計」など）は節に分けず、親の本文に含めている
